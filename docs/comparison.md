# Tesseract.js と Cloud Vision の比較結果

実施日: 2026-11-03

## 条件

| 項目 | 内容 |
|---|---|
| Tesseract | tesseract.js 7.0.0、言語 `jpn+eng`（LSTM）、ブラウザ内で処理 |
| Cloud Vision | `DOCUMENT_TEXT_DETECTION`、`server.py` 経由 |
| 一致率 | 正解テキストと認識結果を NFKC 正規化して空白を除き、`1 − 編集距離 ÷ 長い方の文字数` で計算 |

## 結果

### 合成サンプル（Tesseract）

PoC の「サンプル画像で一括テスト」で生成する 12 パターンの結果です。既定の設定は PSM 3（自動）、前処理なしです。ぼかし＋ノイズはランダムに生成するため、実行のたびに数％ぶれます。

| サンプル | 既定設定 | 設定を変えた場合 |
|---|---|---|
| ① くっきり印刷・ゴシック | 100% | |
| ② 明朝体 | 100% | |
| ③ 小さい文字（12px） | 100% | |
| ④ 傾き 8° | 0% | PSM 6 で 25% |
| ⑤ 低コントラスト | 100% | |
| ⑥ 写真風（ぼかし＋ノイズ） | 100% | |
| ⑦ 照明ムラ・影 | 94% | |
| ⑧ 白抜き文字 | 100% | |
| ⑨ 手書き風フォント | 94% | |
| ⑩ 縦書き | 0% | 縦書き（`jpn_vert`）＋ PSM 5 で 100% |
| ⑪ レシート風（英数字・記号混在） | 45〜54% | PSM 6 で 78% |
| ⑫ 英文 | 100% | |

合成サンプルは Cloud Vision ではまだ計測していません。

### 実際の写真（SNS 投稿）

著作権の都合で、画像はリポジトリに含めていません。

| 画像 | Tesseract | Cloud Vision |
|---|---|---|
| A. 料理写真の上に白文字（横書き 13 行）を重ねた投稿 | 既定設定: 1%<br>白い文字の抽出＋PSM 11: 88%<br>さらに範囲指定: 89〜92% | 正確に読み取れた |
| B. 店舗写真の上に、縁取り付きの大きな縦書きの見出しと横書きの店名を重ねた投稿 | どの設定でも 5% 前後<br>（例: 「北参道と原宿のあいだ」→「北参條刀原窒のあぶだ」） | 正確に読み取れた |

Cloud Vision の結果は目視で確認したもので、一致率は計測していません。

## 分かったこと

- Tesseract は、書類のような画像（白地に黒い文字、文字の大きさがそろっている、横書きまたは縦書きのどちらか一方）なら高精度で読めます。
- 写真の上に重ねた文字は、Tesseract では前処理なしではほぼ読めません。白文字の抽出などで背景を消せば読めるものもありますが、縁取りや影の付いた装飾文字は前処理でも改善しませんでした。
- 傾いた画像、縦書き、表のような配置（レシートなど）は、Tesseract では画像ごとに設定を合わせる必要があります。
- Cloud Vision は、Tesseract が読めなかった写真 A・B のどちらも、設定なしで正確に読み取れました。

## 差が出る理由

一番の差は、文字の認識（読み取り）よりも手前の、**画像の中から文字のある場所を見つける段階**にあります。

| | Tesseract | Cloud Vision |
|---|---|---|
| 想定している画像 | スキャンした書類 | 看板、商品、SNS 投稿など、写真の中のあらゆる文字 |
| 文字の探し方 | 画像全体を白黒にし、黒いかたまりの並びから行を推定する（ルールベース） | 機械学習モデルで、カラー画像から直接「文字がある領域」を見つける |
| 縦書き・横書き | 1 回の実行で、どちらか一方だけ | 文字のかたまりごとに向きを判断する |
| 装飾文字・大きな文字 | 学習データは主に、フォントで普通に描いた書類サイズの文字 | 実際の写真で学習していると考えられる |
| 実行環境 | 数 MB のモデルをブラウザ（WASM）で動かす | Google のサーバーで、より大きなモデルを動かしていると考えられる |

写真 A で、白文字を抽出するだけで一致率が 1% から 88% に上がりました。Tesseract の読み取る力そのものは十分あり、つまずいていたのは文字の場所探しだと分かります。白文字の抽出は、Cloud Vision が自動でやっていることを手作業で再現したことになります。

Cloud Vision の内部構造は詳しく公開されていないため、Cloud Vision 側の説明には推測が含まれます。

## 使い分けの目安

| 用途 | 向いているエンジン |
|---|---|
| ユーザーが撮った写真や SNS 画像など、どんな画像が来るかわからない | Cloud Vision |
| 書類、レシート、名刺など、形式が決まった画像 | Tesseract（前処理と設定を合わせる） |
| 画像を外部に送れない、オフラインで動かしたい、費用をかけたくない | Tesseract |

両方を組み合わせる方法もあります。先に Tesseract で読み、信頼度が低いときだけ Cloud Vision に送れば、費用と外部に送る画像を減らせます。

## 残っている課題

- 合成サンプル 12 種を Cloud Vision でも計測し、両エンジンの差を数値で比べる。
- 実際の写真の枚数を増やし、手書き、レシート、書類などの種類ごとに比べる。
- Cloud Vision の処理時間と費用を、想定する利用量で見積もる。
